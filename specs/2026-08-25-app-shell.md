# 앱 셸 (모바일 프레임 + 하단 네비게이션)

## 목적 (Why)

강아지 쇼핑몰 특성상 실사용자는 대부분 모바일 기기에서 접근하고, 커머스 서비스를 모바일 앱처럼 인식하길 기대한다. 그런데 현재 구현된 홈 화면(및 상품 상세)은 데스크톱 브라우저에서 화면 전체 너비로 퍼지는 반응형 웹사이트 레이아웃이라 이 기대와 어긋난다. 또한 디자인 시스템에 이미 `BottomNav` 컴포넌트가 만들어져 있지만 어디에도 실제로 연결되어 있지 않다. 화면 폭을 모바일 프레임으로 제한하고 하단 네비게이션을 전역에 연결해, 브라우저로 봐도 "웹사이트"가 아니라 "모바일 앱"처럼 인식되는 셸을 구축한다.

## 범위 (Scope)

### In Scope
- 루트 레이아웃(`frontend/src/app/layout.tsx`)에 최대 폭 480px 프레임 적용. 뷰포트가 480px보다 좁으면 프레임이 뷰포트 폭에 맞춰 유동적으로 축소
- 뷰포트가 480px보다 넓을 때 프레임 밖 좌우 여백을 캔버스와 다른 톤의 배경 + `shadow-float`로 시각적으로 구분
- `BottomNav` 컴포넌트를 전역에 실제로 연결: 홈(`/`) / 검색(`/search`) / 장바구니(`/cart`) / 마이페이지(`/mypage`) 4탭, 모든 화면에서 항상 하단 고정 표시, 현재 경로 기준 활성 탭 자동 판정
- `/style-guide` 페이지는 이번 셸 적용에서 제외 (기존처럼 전체 폭 유지)
- 홈 화면(`/`)에 셸을 적용해 1차 검증 (다른 화면은 전역 레이아웃 특성상 자동으로 함께 적용되지만, 시각 검증은 홈 화면 기준으로 진행)
- `specs/2026-08-23-home-screen.md`의 "상품 그리드가 화면 너비에 따라 2열(모바일)~5열(데스크톱) 사이로 반응형 표시된다" AC를 이번 spec으로 대체 — 화면 크기와 무관하게 프레임 폭 기준 항상 2열 고정으로 변경

### Out of Scope
- `/search`, `/cart`, `/mypage` 화면 자체의 실제 구현 (탭 클릭 시 대상 화면이 없어 404가 발생하는 것을 허용 — 기존 home-screen spec의 검색바/장바구니 아이콘과 동일한 전례를 따름. 각 화면은 별도 grillme/spec에서 다룸)
- 위시리스트 기능 자체 (향후 마이페이지 하위 기능으로 흡수될 예정이나, 마이페이지 화면 자체가 이번 범위 밖이므로 함께 범위 밖)
- 상품 상세 페이지(`/products/{id}`)의 콘텐츠 레이아웃/액션 버튼 등 셸 외 변경 (전역 셸에 자동으로 편입되어 프레임+하단 네비 안에서 보이게 되는 것 외에는 기존 spec 그대로)
- PWA 대응(manifest, 서비스워커 등 설치 가능한 앱으로 만드는 작업)
- 헤더 자체의 재설계 (기존 home-screen spec의 헤더 구성·기능은 변경 없이 프레임 안으로 편입됨)

## 사용자 시나리오

1. 사용자가 데스크톱 브라우저(뷰포트 480px 이상)로 momentive에 접속하면, 화면 중앙에 480px 폭 프레임 안에 콘텐츠가 표시되고 프레임 밖 좌우 영역은 다른 톤 배경 + 그림자로 채워져 모바일 앱을 보는 듯한 인상을 준다.
2. 사용자가 모바일 기기(뷰포트 480px 미만)로 접속하면, 프레임이 뷰포트 전체 폭으로 유동적으로 줄어들어 일반적인 모바일 화면과 동일하게 보인다.
3. 화면 하단에는 홈/검색/장바구니/마이페이지 4개 탭의 하단 네비게이션 바가 항상 고정 표시된다. 현재 위치한 화면에 해당하는 탭이 활성 스타일(진한 색 + 굵은 라벨)로 강조된다.
4. 사용자가 홈 탭을 누르면 `/`로 이동한다 (이미 존재하는 화면).
5. 사용자가 검색/장바구니/마이페이지 탭을 누르면 각각 `/search`, `/cart`, `/mypage`로 이동한다. 대상 화면이 아직 없어 현재는 404가 뜨지만 허용한다.
6. 사용자가 홈 화면에서 상품 카드를 눌러 상품 상세 페이지(`/products/{id}`)로 이동해도, 프레임과 하단 네비게이션은 동일하게 유지된다 (전역 셸이므로).
7. 홈 화면의 상품 그리드는 이제 화면 크기와 무관하게 프레임 폭(최대 480px) 안에서 항상 2열로 표시된다 (기존 2~5열 반응형 동작을 대체).
8. `/style-guide` 페이지는 예외적으로 프레임/하단 네비 없이 기존처럼 화면 전체 폭으로 표시된다 (개발용 페이지이므로).

## 인터페이스

### 화면

- **전역 레이아웃 (`frontend/src/app/layout.tsx`)**
  - `children`을 최대 폭 480px 프레임 컨테이너로 감쌈. 뷰포트가 480px 미만이면 프레임 폭은 100%
  - 뷰포트가 480px 초과일 때 프레임 밖 좌우 여백은 캔버스와 다른 톤의 배경색 + `shadow-float`로 프레임 경계를 시각적으로 구분
  - `BottomNav`를 프레임 하단에 고정 렌더링 (프레임 폭과 동일하게 정렬되어, 넓은 화면에서도 하단 네비가 화면 전체 폭이 아닌 프레임 폭 안에만 표시됨)
  - `/style-guide` 라우트는 이 레이아웃 적용에서 제외 (별도 route group 등으로 분리해 전체 폭 유지)
- **BottomNav 탭 구성**
  - 홈: 아이콘 ⌂, 라벨 "홈", 경로 `/`
  - 검색: 아이콘 ⌕, 라벨 "검색", 경로 `/search`
  - 장바구니: 아이콘 🛍, 라벨 "장바구니", 경로 `/cart`
  - 마이페이지: 아이콘 👤, 라벨 "마이페이지", 경로 `/mypage`
  - `activeKey`는 현재 pathname 기준 자동 판정. `/products/{id}`처럼 4개 경로 어디에도 속하지 않는 화면에서는 어떤 탭도 활성화하지 않는다 (모든 탭이 비활성 스타일)
- **홈 화면 (`frontend/src/app/page.tsx`) 변경**
  - 상품 그리드의 반응형 열 수 로직(2~5열)을 제거하고, 프레임 폭 안에서 항상 2열 그리드로 고정
  - 헤더(로고·검색바·히어로 문구·장바구니 아이콘) 구성 자체는 변경 없음, 프레임 안으로 편입되어 렌더링됨

## 수용 기준 (Acceptance Criteria)

- [x] 뷰포트 480px 이상에서 콘텐츠가 480px 폭 프레임 안에 중앙 정렬되어 표시되고, 프레임 밖 영역은 캔버스와 다른 톤 배경 + 그림자로 구분된다
- [x] 뷰포트 480px 미만에서 프레임이 뷰포트 전체 폭으로 유동적으로 표시된다
- [x] 홈, 상품 상세를 포함한 모든 화면(`/style-guide` 제외)에 하단 네비게이션이 항상 하단 고정 표시된다
- [x] 하단 네비 탭이 홈/검색/장바구니/마이페이지 4개로 구성되고, 각각 `/`, `/search`, `/cart`, `/mypage`로 이동한다 (미구현 화면은 404 허용)
- [x] 현재 경로에 해당하는 탭이 활성 스타일로 강조 표시되고, 4개 경로 어디에도 속하지 않는 화면(예: 상품 상세)에서는 모든 탭이 비활성 상태로 표시된다
- [x] `/style-guide` 페이지는 프레임/하단 네비 없이 기존 전체 폭 그대로 유지된다
- [x] 홈 화면의 상품 그리드가 화면 크기와 무관하게 항상 2열로 표시된다
