# app-redesign / Phase 2 — 2026-08-26

## 실패

`frontend/src/app/(shell)/search/page.tsx`의 "입력값 없음 상태: 최근검색어 칩 + 인기검색어 순위 리스트" step(및 spec `2026-08-26-app-redesign.md`의 검색 AC "미입력 상태에서 최근검색어 칩과 인기검색어 순위(1~3위)가 표시되고...") 검증에 실패했다.

`SearchPageInner` 컴포넌트(113~142행)에서 최근검색어/인기검색어 블록의 렌더 조건이 `{!submitted && (...)}`으로만 걸려 있다. 즉 "검색을 아직 실행하지 않았는가"만 확인하고 "입력값이 비어 있는가"는 확인하지 않는다. 그 결과 사용자가 검색어를 입력 중이지만 아직 Enter/클릭으로 실행하지 않은 상태(스펙 시나리오 2 "입력 중" 상태)에서도, 자동완성 드롭다운(98~111행, `suggestions.length > 0`일 때만 표시)과 별개로 최근검색어/인기검색어 섹션이 동시에 화면에 남아있다. 스펙은 "2. 입력 중" 상태와 "3. 입력값 없음" 상태를 서로 다른 화면으로 명시하고 있고, AC도 "미입력 상태에서" 최근검색어/인기검색어가 표시된다고 조건을 명시하므로, 입력 중에도 계속 노출되는 현재 동작은 spec/AC와 어긋난다.

## 원인

구현 시 "검색 실행 여부(`submitted`)"와 "입력값 존재 여부(`query`)"를 하나의 조건(`submitted`)으로만 분기했기 때문이다. 스펙은 이 둘을 별개의 축으로 다룬다 — `submitted=false` 안에서도 `query`가 비어있는지 여부에 따라 자동완성 드롭다운을 보여줄지, 최근/인기검색어 블록을 보여줄지가 갈려야 하는데, 최근/인기검색어 블록 쪽 조건에서 `query`가 비어있는지 체크를 빠뜨렸다.

## 조치

`search/page.tsx`의 최근검색어/인기검색어 블록 조건을 `{!submitted && (...)}` 에서 `{!submitted && !query && (...)}` (혹은 `query.trim().length === 0`)로 수정해, "입력값이 비어 있고 아직 검색을 실행하지 않은" 상태에서만 렌더링되도록 좁혀야 한다. 자동완성 드롭다운 쪽 조건(`suggestions` 계산, 68~71행)은 이미 `!submitted && query`를 전제로 하므로 그대로 두고, 최근/인기검색어 블록만 대칭적으로 `!query` 조건을 추가하면 두 상태(스펙 시나리오 2/3)가 서로 배타적으로 렌더링된다.

## 재발 방지

검색/필터형 화면처럼 "여러 화면 상태(빈 입력/입력 중/실행됨 등)"가 스펙에 번호로 나열돼 있으면, 구현 시 각 상태별 렌더 조건을 스펙 문장 그대로("~일 때", "미입력 상태에서") 하나씩 짚어 boolean 조건에 직접 대응시키고, 상태들이 서로 배타적으로 조건화됐는지(겹치는 조건이 없는지) 코드 리뷰 단계에서 최소 1회 표로 확인한다.
