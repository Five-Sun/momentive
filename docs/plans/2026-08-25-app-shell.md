# 앱 셸 (모바일 프레임 + 하단 네비게이션) 플랜

## 개요

`docs/specs/2026-08-25-app-shell.md`를 기반으로, 전역 모바일 프레임(최대 480px)과 이미 만들어져 있지만 미연결 상태인 `BottomNav`를 실제 라우팅에 연결하고, 홈 화면 상품 그리드를 프레임 폭에 맞춰 2열 고정으로 바꾼다.

`/style-guide`만 셸 적용에서 제외해야 하므로, Next.js route group(`app/(shell)/`)으로 홈(`/`)과 상품 상세(`/products/[id]`)를 묶고 프레임+BottomNav 마크업은 그 그룹의 `layout.tsx`에만 둔다. 루트 `app/layout.tsx`는 폰트/`<html>`/`<body>`만 유지해 `/style-guide`가 자동으로 셸 밖에 위치하도록 한다.

Phase는 검증 가능한 단위로 다음처럼 나눈다.

1. **Phase 1**: route group 분리 + 프레임 컨테이너(배경/그림자/반응형 폭) — BottomNav 없이도 독립적으로 육안 검증 가능
2. **Phase 2**: `BottomNav` 실제 라우팅 연결(활성 탭 판정 포함) — Phase 1의 프레임 위에 올라가는 별도 관심사
3. **Phase 3**: 홈 그리드 2열 고정 + 스펙 전체 AC 회귀 검증 + 빌드/린트

`/search`, `/cart`, `/mypage`는 존재하지 않는 라우트라 Next.js가 루트 not-found로 처리하며, 이 경우 `(shell)` 세그먼트 밖이라 프레임/BottomNav가 씌워지지 않는다. 스펙의 AC는 "미구현 화면은 404 허용"만 요구하고 404 화면에 셸 유지까지 요구하지 않으므로 이는 의도된 동작으로 간주하고 각 phase의 검증 항목에도 그렇게 반영한다.

## Phase 1: 프레임 셸 인프라 + `/style-guide` 제외

이 phase가 끝나면, `/`와 `/products/{id}`가 `app/(shell)/` route group 아래로 이동되어 있고, 뷰포트 480px 기준으로 프레임이 중앙 정렬/유동 축소되며 프레임 밖 영역이 캔버스와 다른 톤 배경+`shadow-float`로 구분된다. `/style-guide`는 기존처럼 전체 폭을 유지한다. BottomNav는 아직 없어도 된다.

- [x] `frontend/src/app/(shell)/` route group 생성, 기존 `app/page.tsx`와 `app/products/[id]/page.tsx`를 그 안으로 이동 (URL은 `/`, `/products/[id]`로 변경 없음, `npm run build`의 라우트 목록으로 확인)
- [x] `frontend/src/app/(shell)/layout.tsx` 작성: 뷰포트 ≥480px에서 콘텐츠가 480px 폭 프레임 안에 중앙 정렬되고 프레임 밖 좌우 영역이 캔버스(`--color-canvas`)와 구분되는 톤의 배경 + `shadow-float`로 표시됨. 기존 토큰 `surface-strong` 재사용 (새 토큰 추가 불필요)
- [x] 같은 레이아웃에서 뷰포트 <480px일 때 프레임 폭이 뷰포트 전체 폭으로 유동적으로 줄어드는 것 확인 (반응형 스타일 적용)
- [x] 루트 `frontend/src/app/layout.tsx`는 폰트 로딩/`<html>`/`<body>`만 유지하고 프레임·네비 관련 마크업을 추가하지 않음 (`/style-guide`가 `(shell)` 그룹 밖에 있어 자동으로 셸 미적용됨을 보장)
- [x] Playwright로 뷰포트 폭 1280px/390px 스크린샷 비교해 프레임 동작 확인, `/style-guide` 접속 시 기존과 동일하게 프레임 없이 전체 폭으로 표시되는지 확인 (`npm run build` 라우트 목록도 `/`, `/products/[id]`, `/style-guide`, `/_not-found`로 변경 없음 확인)

## Phase 2: BottomNav 전역 연결

이 phase가 끝나면, `(shell)` 그룹의 모든 화면(홈, 상품 상세) 하단에 `BottomNav`가 고정 표시되고, 현재 경로에 따라 올바른 탭이 활성화되며, 탭 클릭 시 해당 경로로 이동한다 (`/search`, `/cart`, `/mypage`는 404 허용).

- [x] `frontend/src/components/navigation/GlobalBottomNav.tsx` 작성: 홈(`/`, ⌂)/검색(`/search`, ⌕)/장바구니(`/cart`, 🛍)/마이페이지(`/mypage`, 👤) 4탭을 `BottomNav`의 `items`로 구성 — 기존 `BottomNav` 컴포넌트(`components/navigation/BottomNav.tsx`)의 props/구현은 변경하지 않음
- [x] `usePathname` 기준으로 `activeKey` 계산: 현재 경로가 4개 탭 경로 중 하나와 일치하면 해당 키, 그 외(`/products/{id}` 등)에는 빈 문자열을 넘겨 전부 비활성 처리
- [x] `onSelect`에서 `useRouter().push()`로 탭 선택 시 해당 경로로 실제 이동
- [x] `frontend/src/app/(shell)/layout.tsx` 하단에 `sticky bottom-0`으로 이 wrapper를 마운트, 프레임 폭 안에서 하단 고정 표시(넓은 화면에서도 뷰포트 전체 폭이 아닌 프레임 폭에 맞춰 정렬). 홈 화면 `<section>`의 하단 패딩을 BottomNav 높이(64px)에 맞춰 `pb-12`→`pb-20`으로 조정(마지막 상품 줄이 가려지는 것 방지, 플랜 범위를 벗어난 필수 보완 사항)
- [x] Playwright 수동 검증: `/`에서 홈 탭 활성(핑크+굵게) 확인 → 상품 상세(`/products/{id}`)로 이동 시 프레임/BottomNav 유지되고 4탭 모두 비활성 확인 → `/search` 이동 시 404(허용된 동작) 확인
  - 검증 중 발견: `globals.css`의 composite 타이포 클래스(`.text-caption` 등)가 `@layer utilities`로 선언되어 있어 Tailwind의 `font-bold`보다 CSS 소스 순서상 나중에 적용되면서 항상 이겨버림 → 활성 탭이 색상만 바뀌고 굵게 표시되지 않는 버그 발견 (BottomNav뿐 아니라 `Rating.tsx`의 평점 숫자도 동일하게 영향받고 있었음). `@layer components`로 옮겨 Tailwind 유틸리티 레이어보다 우선순위를 낮춰 해결 (플랜 범위를 벗어난 디자인 시스템 레벨 버그 수정, `BottomNav.tsx`/`Rating.tsx` 자체는 변경하지 않음)

## Phase 3: 홈 그리드 2열 고정 + 전체 회귀 검증

이 phase가 끝나면, 홈 화면 상품 그리드가 화면 크기와 무관하게 항상 2열로 표시되고, 스펙의 7개 수용 기준이 전부 충족되며 빌드/린트가 통과한다.

- [x] `frontend/src/app/(shell)/page.tsx`의 상품 그리드 클래스를 `grid-cols-2 sm:grid-cols-3 lg:grid-cols-4 xl:grid-cols-5`에서 `grid-cols-2` 고정으로 변경 (반응형 열 수 분기 제거)
- [x] 헤더(로고·검색바·히어로 문구·장바구니 아이콘) 등 그리드 외 나머지 홈 화면 구성은 변경 없음을 확인
- [x] 스펙(`docs/specs/2026-08-25-app-shell.md`)의 수용 기준 7개를 뷰포트 폭을 바꿔가며(1280px, 390px) Playwright 스크린샷으로 전부 재검증:
  - [x] ≥480px에서 480px 프레임 중앙 정렬 + 프레임 밖 배경/그림자 구분
  - [x] <480px에서 프레임이 뷰포트 전체 폭으로 유동 표시
  - [x] 홈/상품 상세(`/style-guide` 제외) 모든 화면에 BottomNav 하단 고정 표시
  - [x] BottomNav 4탭이 각각 `/`,`/search`,`/cart`,`/mypage`로 이동 (미구현 화면 404 허용)
  - [x] 현재 경로에 해당하는 탭만 활성 스타일(색상+굵게), 상품 상세처럼 4경로 밖이면 전부 비활성
  - [x] `/style-guide`는 프레임/BottomNav 없이 기존 전체 폭 유지
  - [x] 홈 화면 상품 그리드가 화면 크기(1280px/390px)와 무관하게 항상 2열
- [x] `npm run build` 통과 확인
- [x] `npm run lint` 통과 확인
