# 모멘티브 도메인 개요

grillme로 기능별 spec을 쓰기 시작하기 전, 여러 spec에 걸쳐 재사용될 핵심 엔티티와 전체 기능 우선순위를 잡아두는 가벼운 참고 문서다. `specs/`처럼 이력을 누적하는 문서가 아니라 **살아있는 참고 문서** — spec을 진행하며 엔티티 정의가 더 정확해지면 이 문서를 그때그때 갱신한다.

이 문서 자체는 spec-format.md/plan-format.md 같은 규격이 아니다. 각 기능의 정확한 필드/제약조건은 해당 기능의 spec(데이터 모델 섹션)에서 확정한다 — 여기서는 큰 그림만 잡는다.

## 핵심 엔티티 (초안)

- **User** — 구매자. 관리자 계정을 별도로 둘지는 회원가입/로그인 spec에서 결정
- **Product** — 상품. 카테고리/재고/가격 등 상세 필드는 상품 조회 spec에서 확정
- **Cart** — 장바구니. User와 1:1로 둘지 비회원 세션 기반도 지원할지는 장바구니 spec에서 결정
- **Order** — 주문. 여러 Product(주문 시점 스냅샷)를 참조, User에 속함
- **Payment** — 결제. Order와 1:1, 토스페이먼츠 연동 (샌드박스 → 실결제 전환 예정)

## 관계 (대략)

```
User 1─N Order
Order 1─N OrderItem ─N:1─ Product
Order 1─1 Payment
User 1─1 Cart (또는 비회원 세션 카트)
```

## 기능 목록 (우선순위순)

1. **상품 목록/상세 조회** — 인증·결제 의존성 없음. spec→plan→backend→frontend→배포 파이프라인을 가장 낮은 리스크로 검증하는 첫 기능
2. **회원가입/로그인** — 장바구니·주문의 전제조건
3. **장바구니**
4. **주문/결제 (토스페이먼츠)**
5. **마이페이지 (주문내역)**
6. **관리자 상품 관리**

## 사용 방법

- grillme 세션 시작 전 이 문서를 훑어 엔티티 명칭·관계를 spec 간에 일관되게 유지한다
- spec 작성 중 여기 정의와 다르게(또는 더 정확하게) 결정된 사항이 있으면 이 문서를 갱신한다
- 새 기능이 여기 목록에 없으면, spec을 쓰기 전에 이 문서에 먼저 추가할지 판단한다 (사소한 하위 기능이면 생략 가능)
