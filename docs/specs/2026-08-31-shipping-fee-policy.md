# 배송비 정책 반영

## 목적 (Why)

`cart-order-payment`(`docs/specs/2026-08-29-cart-order-payment.md`)는 "배송비 없음(상품가만 결제)"으로 구현됐지만, 실제 사업자 배송비 정책(네이버 스마트스토어 기준: 기본 3,400원, 7만원 이상 무료배송, 제주/도서산간 +4,000원)과 불일치한다. `mypage-menu-cleanup`(`docs/specs/2026-08-31-mypage-menu-cleanup.md`) 세션 중 고객센터 FAQ에 실제 정책을 반영하면서 이 불일치가 드러났으나, 당시엔 결제 로직 수정을 범위 밖으로 분리하고 후속 후보로 남겨뒀다. 결제가 아직 샌드박스 단계라 지금 당장 실 고객이 손해를 보는 상황은 아니지만, 실결제 전환 전에 청구 금액과 FAQ 안내 문구가 일치해야 한다.

## 범위 (Scope)

### In Scope
- 주문 생성 시 배송비 계산: 기본 3,400원 / 상품금액(주문 상품 subtotal) 70,000원 이상이면 기본 배송비 무료 / 배송지가 제주(우편번호 63000~63644)면 상품금액과 무관하게 4,000원 항상 추가
- `Order`에 배송비를 별도 필드로 저장하고, 총 결제금액(`totalAmount`)이 상품금액+배송비 합계를 반영하도록 확장
- 체크아웃 화면에 상품금액/배송비/총 결제금액 breakdown 표시
- 마이페이지 주문상세 화면에 동일한 breakdown 표시
- 장바구니 화면에 무료배송까지 남은 금액 안내 — 기존에 만들어져 있으나 연결되어 있지 않던 `ShippingProgress` 컴포넌트(`frontend/src/components/feedback/ShippingProgress.tsx`)를 기준금액 70,000원으로 갱신해 재활용, 체크박스로 **선택된** 상품 subtotal 기준으로 계산

### Out of Scope
- 제주 외 도서산간(울릉도, 흑산도, 백령도 등) 할증 — 우편번호만으로 정확히 판정하기 어려워 후속 후보로 분리(`Todo.md`에 기록)
- 우편번호 형식 검증(5자리 숫자 등) — `AddressRequest.zipcode`는 현재 형식 검증이 없는 자유 텍스트. 정식 검증 도입은 기존 저장 데이터 하위호환까지 고려해야 해서 범위 밖(`Todo.md`에 기록). 이번 spec의 제주 판정 로직은 숫자 파싱 실패/범위 밖 값을 안전하게 "제주 아님"으로 처리
- 쿠폰 시스템과의 연동 — 장바구니의 쿠폰 할인은 현재 결제 금액에 실제로 반영되지 않는 UI placeholder이며, 이 상태를 그대로 유지(무료배송 임계값도 할인 적용 전 상품금액 기준)
- 배송비 환불/부분환불 로직 — 기존 `cart-order-payment`와 동일하게 범위 밖(현재 주문 취소는 PG 환불 호출 없이 재고만 원복)
- Toss 결제위젯 실연동 검증 — 상점(스토어) 등록 대기 중인 별도 이슈(`docs/backlog/2026-08-30-cart-order-payment-phase4-01.md`)로, 이번 spec은 서버가 계산한 금액이 위젯/confirm에 정확히 전달되는지까지만 확인

## 사용자 시나리오

1. 사용자가 장바구니에서 상품 여러 개를 담고 일부를 체크박스로 선택한다. 선택된 상품 합계가 70,000원 미만이면 "OO원 더 담으면 무료배송" 안내가, 70,000원 이상이면 "무료배송 조건을 달성했어요" 안내가 표시된다. 체크 해제하면 선택 금액이 줄어들며 안내가 다시 미달성으로 바뀔 수 있다.
2. 사용자가 "구매하기"를 눌러 체크아웃 화면으로 이동해 배송지를 선택(또는 신규 입력)한다. 화면에 "상품금액 / 배송비 / 총 결제금액" 3줄이 표시된다.
   - 상품금액이 70,000원 미만이고 배송지가 제주가 아니면 배송비 3,400원
   - 상품금액이 70,000원 이상이고 배송지가 제주가 아니면 배송비 0원("무료")
   - 상품금액이 70,000원 미만이고 배송지가 제주(우편번호 63000~63644)면 배송비 7,400원(3,400+4,000)
   - 상품금액이 70,000원 이상이고 배송지가 제주면 배송비 4,000원(제주 할증만 남음)
3. 사용자가 "결제하기"를 누르면 주문이 생성되고, 결제위젯에는 상품금액+배송비를 합한 금액이 렌더링된다. Toss 결제 승인(confirm) 시에도 이 금액으로 검증된다(기존 `order.totalAmount` 단일 소스 구조를 그대로 활용하므로 위젯/confirm 쪽 별도 변경 없이 정확한 금액이 자동으로 흐른다).
4. 결제 완료 후 마이페이지 주문상세에서 해당 주문의 상품금액/배송비/총 결제금액을 다시 확인할 수 있다.

## 인터페이스

### API

- `POST /orders` (`OrderCreateRequest` → `OrderResponse`): 요청 계약은 변경 없음. 응답에 아래 필드가 추가된다.
- `GET /orders/{orderId}` (`OrderResponse`): 위와 동일하게 필드 추가.
- `OrderResponse` 추가 필드:
  - `itemsSubtotal` (Integer): 배송비를 제외한 주문 상품 금액 합계
  - `shippingFee` (Integer): 위 사용자 시나리오 2의 규칙으로 계산된 배송비
  - `totalAmount` (기존 필드, 의미 확장): `itemsSubtotal + shippingFee`
- `GET /orders`(목록, `OrderSummaryResponse`)는 변경하지 않는다 — 이미 `totalAmount` 총액 한 줄만 노출하고 breakdown을 보여주지 않으므로 그대로 유지.
- 결제위젯 렌더링 금액(`checkout/payment/page.tsx`)과 confirm 요청 금액 검증(`OrderPaymentTransactionSupport.assertPendingAndOwned`)은 기존처럼 `order.totalAmount`를 그대로 참조하는 구조이므로 별도 계약 변경이 없다.

### 화면

- **장바구니(`/cart`)**: 상품 목록과 "총 결제금액" 사이에 `ShippingProgress` 컴포넌트를 배치. `remaining = max(0, 70000 - 선택된 상품 subtotal)`을 넘겨 렌더링. 배송비 실금액(제주 할증 포함)은 배송지를 아직 모르므로 이 화면에서는 계산/표시하지 않는다.
- **체크아웃(`/checkout`)**: 기존 "총 결제금액" 한 줄을 "상품금액 / 배송비 / 총 결제금액" 3줄로 확장. 배송지가 선택되거나 새로 입력될 때마다(제주 여부 판정 대상이 바뀔 때) 배송비를 다시 계산해 표시한다. 주문 생성(`POST /orders`) 성공 후에는 응답의 `totalAmount`가 결제위젯에 그대로 전달된다.
- **마이페이지 주문상세(`/mypage/orders/[orderId]`)**: 기존 "총 결제금액" 한 줄을 체크아웃과 동일하게 "상품금액 / 배송비 / 총 결제금액" 3줄로 확장.

### 데이터 모델

- `Order` 엔티티에 `shippingFee` (Integer, not null) 컬럼 추가. `totalAmount`는 기존 컬럼을 유지하되 `itemsSubtotal + shippingFee`로 계산되어 저장된다.
- 정책 상수: 기본 배송비 3,400원 / 무료배송 임계값 70,000원(상품금액 기준) / 제주 할증 4,000원 / 제주 판정 우편번호 범위 63000~63644(문자열 `zipcode`를 정수로 파싱해 판정, 파싱 실패 시 제주 아님으로 처리)
- Flyway 마이그레이션으로 `orders.shipping_fee` 컬럼을 추가한다.

## 수용 기준 (Acceptance Criteria)

- [ ] 상품금액 70,000원 미만 + 비제주 배송지로 주문 시 배송비 3,400원이 부과되고 `totalAmount`에 반영된다
- [ ] 상품금액 70,000원 이상 + 비제주 배송지로 주문 시 배송비 0원(무료)으로 `totalAmount`에 반영된다
- [ ] 배송지 우편번호가 63000~63644(제주) 범위면 상품금액과 무관하게 배송비에 4,000원이 항상 추가된다 (70,000원 미만: 7,400원, 이상: 4,000원)
- [ ] 우편번호가 숫자로 파싱되지 않거나 범위 밖이면 제주 할증 없이 안전하게 처리된다
- [ ] 체크아웃 화면에 상품금액/배송비/총 결제금액이 각각 별도 줄로 표시된다
- [ ] 마이페이지 주문상세 화면에 상품금액/배송비/총 결제금액이 각각 별도 줄로 표시된다
- [ ] 장바구니 화면에서 선택된 상품 합계가 70,000원 미만이면 "OO원 더 담으면 무료배송" 안내가, 이상이면 달성 안내가 표시된다 (`ShippingProgress` 기준금액이 70,000원으로 갱신되어 반영됨)
- [ ] 체크아웃에서 배송지를 바꿔 제주 ↔ 비제주 전환 시 배송비 표시와 최종 `totalAmount`가 즉시 재계산된다
- [ ] Toss 결제위젯에 렌더링되는 결제 금액과 confirm 시 검증 금액이 배송비 포함 총액과 일치한다
