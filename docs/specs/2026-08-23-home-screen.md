# 홈 화면

## 목적 (Why)

`docs/specs/2026-08-18-product-catalog.md`가 "홈(`/`) = 상품 목록"이라는 기능 계약(API, 데이터 모델, 수용 기준)을 이미 확정했지만, 그 스펙의 "화면" 섹션은 구성 요소와 상태만 정의하고 실제 시각 디자인(레이아웃, 컴포넌트 배치, 브랜드 톤)은 다루지 않는다. 별도로 구축해둔 모멘티브 디자인 시스템(`frontend/src/components/`)을 적용해 홈 화면의 실제 UI를 구체화하기 위한 스펙이다.

## 범위 (Scope)

### In Scope
- 홈 화면(`/`)의 레이아웃: 헤더(로고·검색바·히어로 문구·장바구니 아이콘), 상품 그리드, 무한스크롤
- 상품 카드의 시각 구성: 대표 이미지, 위시(하트) 버튼, 뱃지, 상품명, 평점, 가격/할인가 — 단 위시·평점은 UI 배치만 하고 클릭 동작은 없음(더미)
- 검색바·장바구니 아이콘: UI 배치와 `/search`, `/cart`로의 이동 링크만 (대상 화면 자체는 이번 범위 밖)
- 빈 상태 메시지 문구, 로딩 스켈레톤, 이미지 로드 실패 시 플레이스홀더
- 반응형 그리드 열 수(화면 너비에 따라 2~5열)

### Out of Scope
- `/search`, `/cart` 화면 자체의 구현 (각각 별도 grillme/spec에서 다룸)
- 카테고리 분류/필터 (Product 모델에 category 필드 없음 — 확장 시 별도 세션에서 결정)
- 위시리스트 기능의 실제 저장/조회, 평점 집계 기능 (데이터 모델·API 없음 — UI 자리만 예약)
- 백엔드 구현 및 plan 작성 (product-catalog 스펙의 API 계약을 그대로 따르며, 실행 순서는 이후 별도 plan에서 결정)
- product-catalog 스펙에서 이미 정의한 API 계약, 데이터 모델, 수용 기준 (변경 없음, 그대로 참조)

## 사용자 시나리오

1. 사용자가 루트(`/`)에 접속하면 홈 화면이 나타난다.
2. 상단에는 momentive 로고, 검색바("브랜드, 상품 검색" placeholder), "소중한 순간을 위한 옷" 히어로 문구, 장바구니 아이콘이 순서대로 노출된다.
   - 검색바를 클릭하면 `/search`로 이동한다 (화면 미구현 상태이므로 현재는 404).
   - 장바구니 아이콘을 클릭하면 `/cart`로 이동한다 (화면 미구현 상태이므로 현재는 404).
3. 그 아래 상품 그리드가 나타난다. 화면 너비에 따라 2~5열로 가변한다.
4. 각 상품 카드는 대표 이미지, 우상단 하트(위시) 버튼, 좌상단 뱃지(할인율/NEW/품절 등), 상품명, 평점(더미 값 또는 표시 안 함), 가격(할인가 있으면 정가 취소선 + 할인가 병기)을 보여준다.
   - 하트 버튼은 클릭해도 상태가 바뀌지 않는다 (위시리스트 기능은 이번 범위 밖).
5. 사용자가 그리드 하단까지 스크롤하면 다음 페이지(20개)가 자동으로 로드되어 이어붙는다 (무한스크롤). API는 product-catalog 스펙의 `GET /products?page&size` 계약을 그대로 사용한다.
6. 사용자가 상품 카드를 클릭하면 상세 페이지(`/products/{id}`)로 이동한다 (product-catalog 스펙에 정의된 동작, 변경 없음).
7. 예외 케이스:
   - 데이터 fetch 중에는 카드와 동일한 레이아웃의 회색 스켈레톤이 그리드에 표시된다.
   - 상품이 하나도 없으면 그리드 대신 브랜드 톤의 다정한 빈 상태 문구("아직 준비된 상품이 없어요" 등)를 보여준다.
   - 상품 이미지가 없거나 로드에 실패하면 `surface-strong` 배경에 상품명 텍스트를 표시하는 플레이스홀더로 대체한다.

## 인터페이스

### 화면

- **홈 페이지 (`/`)**
  - **헤더**: momentive 로고(원형) · `SearchInput` 컴포넌트(placeholder "브랜드, 상품 검색", 클릭 시 `/search`로 이동) · 히어로 텍스트("소중한 순간을 위한 옷") · 장바구니 아이콘 버튼(클릭 시 `/cart`로 이동)
  - **상품 그리드**: `ProductCard` 컴포넌트 반복. 화면 너비 기준 2~5열 반응형(예: 모바일 2열, 태블릿 3열, 데스크톱 4~5열)
    - `ProductCard` 표시 항목: 대표 이미지(`aspect-square`, 없거나 실패 시 `surface-strong` 배경 + 상품명 텍스트), 하트 버튼(우상단, 클릭 무동작), 뱃지(좌상단, 할인율/NEW/품절 등 — product-catalog의 `soldOut` 필드 및 할인 여부 기반), 상품명, 평점(더미 표시, 실데이터 없음), 가격(할인가 있으면 정가 취소선 + 할인가)
  - **무한스크롤**: 그리드 하단 도달 시 다음 페이지(`page+1`, `size=20`)를 자동 fetch해 이어붙임. API 계약은 product-catalog 스펙의 `GET /products` 그대로
  - **빈 상태**: 상품이 0개일 때 그리드 대신 문구 표시 (예: "아직 준비된 상품이 없어요")
  - **로딩 상태**: 초기 로드 및 추가 페이지 로드 중 `ProductCard`와 동일한 크기의 회색 스켈레톤 박스를 그리드에 표시
  - 상품 카드 클릭 시 `/products/{id}`로 이동 (product-catalog 스펙 동작 재사용)

- [x] 검색바 클릭 시 `/search`로, 장바구니 아이콘 클릭 시 `/cart`로 이동한다 (대상 화면 미구현으로 인한 404는 허용)
- [x] 상품 그리드가 화면 너비에 따라 2열(모바일)~5열(데스크톱) 사이로 반응형 표시된다
- [x] 각 상품 카드가 대표 이미지, 하트 버튼(클릭 무동작), 뱃지, 상품명, 가격/할인가를 표시한다

- [x] 그리드 하단 스크롤 도달 시 다음 20개 상품이 자동으로 추가 로드된다
- [x] 데이터 fetch 중에는 카드 형태의 회색 스켈레톤이 표시된다
- [x] 상품이 0개일 때 브랜드 톤의 빈 상태 문구가 그리드 대신 표시된다
- [x] 상품 카드 클릭 시 `/products/{id}` 상세 페이지로 이동한다
