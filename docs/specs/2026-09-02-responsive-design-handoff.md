# 디자인 핸드오프 2차 이관 (폰트·모션·데스크톱 반응형)

## 목적 (Why)

`design_handoff_momentive_app` 핸드오프의 1차 이관(`docs/specs/2026-08-26-app-redesign.md`, PR #3)에서 색상·radius·shadow·spacing·타이포 스케일은 이미 값까지 동일하게 반영됐다. 이번 2차 핸드오프에서 새로 확정된 항목 3가지가 아직 반영되지 않은 상태다.

1. **폰트** — 클라이언트가 브랜드 서체로 어비 세현체(UhBeeSehyun)를 지정했다. 현재는 1차 이관 당시 "로고 서체 대체용"으로 임시 채택한 Google Fonts `Jua`(디스플레이) + `Noto Sans KR`(본문)를 쓰고 있어, 브랜드가 의도한 손글씨 톤이 화면에 전혀 반영돼 있지 않다.
2. **모션** — `tokens/motion.css`의 `paw-pop`/`bump-up`/`--ease-spring`이 현재 코드베이스에 **전혀 존재하지 않는다**. 하트 토글·칩 선택·탭 활성화·토스트 등장이 전부 무반응이라, 핸드오프가 브랜드 톤의 핵심으로 지정한 "작고 다정한 미세 인터랙션"이 빠져 있다.
3. **데스크톱 반응형** — 현재 앱은 `max-w-[480px]` 폰 목업 프레임에 고정돼 있어, 데스크톱에서 접속하면 화면 양옆이 전부 빈 공간이다. 실 고객이 있는 운영 쇼핑몰인데 데스크톱 유입이 사실상 버려지고 있다.

부수적으로, `frontend/CLAUDE.md`가 **필수** 컨벤션으로 4회 참조하고 `frontend-reviewer`가 검증 기준으로 삼는 `docs/design.md`가 리포지토리에 존재하지 않는다. 이번 작업이 토큰·컴포넌트·반응형 규칙을 전면적으로 건드리므로, 이 문서를 함께 작성해 리뷰 기준의 공백을 해소한다.

## 범위 (Scope)

### In Scope

- 어비 세현체 self-host 도입 및 전 화면 적용 (fallback `Noto Sans KR`)
- `paw-pop`/`bump-up`/`--ease-spring` 모션 토큰 도입 및 지정 지점 적용
- `(shell)` 하위 전체 18개 라우트의 데스크톱(≥1024px) 반응형 대응 (핸드오프 레퍼런스가 있는 7개 + 없는 11개)
- 앱 셸(`(shell)/layout.tsx`) 폰 목업 프레임 제거 및 반응형 컨테이너로 전환
- 데스크톱 상단 가로 네비게이션(`TopNav`) 신설, 하단 탭바의 1024px 분기
- 공통 컴포넌트의 반응형·모션 대응
- `docs/design.md` 신규 작성
- `/style-guide` 갱신 (BottomNav 4탭→5탭 드리프트 정정 + 신규 토큰 샘플)

### Out of Scope

- **레퍼런스의 목업 비즈니스 로직 이관** — `ui_kits/web-app/index.html`과 `README.md`가 담고 있는 무료배송 5만원 임계값, 장바구니 쿠폰 3,000원 하드코딩 토글, 하드코딩 평점/리뷰는 이관하지 않는다. 실운영 로직(무료배송 70,000원 + 제주 4,000원 할증, 실제 쿠폰 시스템, 실제 리뷰 집계)이 우선한다.
- **화면 내용물 재설계** — `web-app/index.html`은 프로토타입 축약본이라 검색 화면이 없고(`onSearch`가 빈 함수) 상품상세에 리뷰·사이즈가이드·배송 아코디언이 없다. 이 축약을 근거로 기존 구현을 삭제하지 않는다.
- **`mobile-app/index.html` 기준 재설계** — 레이아웃 기준으로 사용하지 않는다.
- **Known gaps의 실제 자산 교체** — 실제 아이콘 세트(현행 `lucide-react` 유지)와 실제 상품/리뷰 사진(현행 플레이스홀더 유지). 교체 지점만 표시한다.
- 로고 이미지 교체 및 재창작
- 관리자 상품 관리, Toss 결제위젯 실연동, 우편번호 형식 검증 (각각 별도 Todo 후보)
- 데이터 페칭 전략 변경, 백엔드 변경 일체

## 사용자 시나리오

### 1. 모바일 웹 고객 (<1024px) — 기존 경험 유지 + 폰트/모션 변화

1. 고객이 모바일 브라우저로 접속하면 홈이 뜬다. 하단에는 기존과 동일하게 **5탭**(홈/카테고리/검색/위시/마이) 탭바가 있다.
2. 모든 텍스트가 어비 세현체로 렌더된다. 폰트는 자체 서버에서 서빙되며, 로드 전에도 `Noto Sans KR`로 폴백돼 텍스트가 사라지지 않는다.
3. 상품 카드의 하트를 누르면 하트가 `paw-pop`으로 튕기고(scale 1→1.28→.94→1), 카테고리 칩을 선택해도 같은 모션이 걸린다.
4. 하단 탭을 옮기면 활성 탭 아이콘에 `bump-up`이 걸린다.
5. 장바구니에 담으면 토스트가 spring 이징으로 아래에서 올라와 1.8초 뒤 사라진다.
6. 화면 폭이 480px보다 넓은 모바일/태블릿에서는 콘텐츠가 480px로 가운데 정렬되며, 기존의 흰 프레임·그림자 테두리는 더 이상 보이지 않는다.
7. OS에서 "동작 줄이기"를 켠 고객에게는 위 모션이 모두 비활성화되고 상태 변화만 즉시 반영된다.

### 2. 데스크톱 고객 (≥1024px) — 신규 경험

1. 데스크톱으로 접속하면 하단 탭바 대신 **상단 가로 네비**가 뜬다. 좌측에 로고, 그 옆에 4개 링크(홈/카테고리/위시/마이), 우측에 검색 입력창과 장바구니 아이콘(수량 배지)이 있다. 검색은 상단 입력창이 상시 노출되므로 네비 링크에서 제외된다.
2. 콘텐츠는 최대 1400px 폭으로 가운데 정렬된다.
3. 홈/검색/위시리스트의 상품 그리드가 1024px 이상에서 **3열**, 1280px 이상에서 **4열**로 늘어난다.
4. 상품상세에 들어가면 좌측에 상품 이미지가 스크롤을 따라 고정(sticky)되고, 우측에 제목·평점·가격·사이즈 선택·CTA가 배치된다. 리뷰 목록과 사이즈가이드·배송/교환 아코디언은 그 아래 전체폭으로 이어진다.
5. 장바구니와 체크아웃은 좌측 본문 + **우측 340px 요약 컬럼** 2단으로 나뉘고, 결제 CTA는 요약 컬럼 안에 sticky로 붙는다. 모바일에서 쓰던 화면 하단 고정 CTA 바는 데스크톱에서 나타나지 않는다.
6. 상품상세·주문상세 등 나머지 화면의 하단 고정 CTA도 데스크톱에서는 고정이 풀려 콘텐츠 흐름 안에 배치된다.
7. 브라우저 폭을 1024px 경계 위아래로 조절하면 상단 네비 ↔ 하단 탭바가 즉시 전환되며, 어느 쪽에서도 CTA가 네비게이션에 가려지지 않는다.

### 3. 레퍼런스가 없는 화면의 데스크톱 (로그인/회원가입/체크아웃/주문내역/쿠폰함/반려견/고객센터)

1. 핸드오프에 데스크톱 디자인이 없는 11개 화면은 아래 기본 규칙으로 직접 설계한다.
2. 폼 중심 화면(로그인·회원가입)은 콘텐츠를 480px 폭으로 유지하고 화면 중앙에 배치한다 — 폼 필드를 1400px로 늘리지 않는다.
3. 목록 중심 화면(주문내역·쿠폰함·반려견)은 카드 목록을 최대 폭 안에서 넓히되, 항목이 지나치게 가로로 늘어나지 않도록 다단 배치 또는 최대 폭 제한을 적용한다.
4. 정적 문서 화면(고객센터 FAQ)은 가독 폭(약 720px)으로 제한한다.

### 예외/엣지 케이스

- **폰트 로드 실패**: self-host 파일이 로드되지 않으면 `Noto Sans KR`로 폴백된다. 레이아웃이 깨지지 않아야 한다.
- **미커버 글리프**: 어비 세현체는 한글 2,449자만 수록한다. 서비스 UI 카피·상품 시드 데이터는 전량 커버됨을 사전 실측으로 확인했으나(미커버 0건), 사용자 생성 콘텐츠(닉네임·리뷰·주소)에 미수록 음절이 오면 해당 글자만 `Noto Sans KR`로 폴백된다. 이는 허용된 동작이다.
- **굵기 위계**: 어비 세현체는 Regular 1종만 존재한다. 타이포 스케일 10개 중 7개가 weight 500~700이므로 브라우저 synthetic bold로 렌더된다. `text-tag`(11px)·`text-caption`(12px)에서 획이 뭉개져 판독이 어려우면 **해당 토큰만 weight 400으로 평탄화**한다. 다른 서체로 대체하지 않는다.

## 인터페이스

### 화면

#### 브레이크포인트

| 구간 | 네비게이션 | 콘텐츠 폭 | 상품 그리드 |
|---|---|---|---|
| < 1024px | 하단 탭바 5탭 | 최대 480px 중앙 정렬 | 2열 |
| ≥ 1024px | 상단 가로 네비 4탭 + 검색창 | 최대 1400px 중앙 정렬 (좌우 40px 패딩) | 3열 |
| ≥ 1280px | 상단 가로 네비 | 최대 1400px | 4열 |

#### 앱 셸 (`src/app/(shell)/layout.tsx`)

- 기존 `bg-surface-strong` 배경 + `max-w-[480px]` 흰 프레임 + `shadow-float` 구조를 **제거**한다. `shadow-float`는 핸드오프상 toast/bottom sheet 전용 토큰이므로 셸에서 사용하지 않는다.
- <1024px: 콘텐츠 `max-w-[480px] mx-auto`, 배경은 `canvas`
- ≥1024px: 콘텐츠 `max-w-[1400px] mx-auto`, 좌우 패딩 40px

#### 네비게이션

- **`TopNav`(신규, `src/components/navigation/`)** — ≥1024px에서만 렌더. 높이 80px, 하단 `border-hairline` 1px. 좌측 로고(38px 원형) + 링크 4개(홈/카테고리/위시/마이), 우측 검색 입력창(높이 42px, 폭 300px, `surface-soft` 배경, pill) + 장바구니 아이콘(수량 배지 `brand-pink-active`). 활성 링크는 `brand-pink-active` + bold.
- **`GlobalBottomNav`** — <1024px에서만 렌더. 탭 구성(5탭)과 `href`는 현행 유지. 활성화 시 아이콘에 `bump-up` 적용.
- 데스크톱에서는 하단 탭바가 없으므로, 현행 `HIDDEN_PREFIXES`(`/checkout`, `/mypage/orders/`) 우회는 <1024px에만 적용된다.

#### 폰트

- 어비 세현체 woff2를 `frontend/public/fonts/`에 두고 `next/font/local`로 로드한다. 외부 CDN(`cdn.jsdelivr.net`) 직접 참조는 사용하지 않는다.
- CSS 변수로 노출해 `globals.css`의 `--font-display`/`--font-body`가 모두 어비 세현체를 가리키게 한다. fallback은 `Noto Sans KR`.
- 타이포 스케일 10종의 크기/줄높이/weight 값은 **변경하지 않는다**(1차 이관과 동일).
- 기존 `Jua`는 제거한다.

#### 모션 (`globals.css`)

| 토큰 | 정의 | 적용 지점 |
|---|---|---|
| `--ease-spring` | `cubic-bezier(.34,1.56,.64,1)` | Toast 등장(translateY + scale) |
| `paw-pop` | scale 1 → 1.28(45%) → .94(70%) → 1 | 위시 하트 토글, 칩 선택, Badge |
| `bump-up` | translateY 0 → -3px & scale 1.15(50%) → 0 | 하단 탭 활성화 |

- CSS `@keyframes` + Tailwind `animate-*` 유틸로 구현한다. Framer Motion 등 신규 의존성을 추가하지 않는다.
- 화면 전환 등 큰 모션에는 사용하지 않는다.
- `@media (prefers-reduced-motion: reduce)`에서 위 애니메이션을 모두 비활성화한다.

## 수용 기준 (Acceptance Criteria)

- [ ] 어비 세현체 woff2가 `frontend/public/fonts/`에서 self-host되고, `next/font/local`로 로드되며, 소스 어디에도 `cdn.jsdelivr.net` 폰트 참조가 없다
- [ ] 전 화면 텍스트가 어비 세현체로 렌더되고, fallback 체인에 `Noto Sans KR`이 있다. `Jua` 참조가 코드베이스에서 제거됐다
