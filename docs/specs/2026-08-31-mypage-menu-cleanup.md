# 마이페이지 메뉴 정리 (반려견 프로필 관리 + 고객센터)

## 목적 (Why)

마이페이지 하단 메뉴 5개(배송조회/쿠폰함/적립금/반려견 프로필 관리/고객센터)가 전부 `onClick={() => {}}`로 완전 무동작 상태다. 실제 고객이 있는 서비스에서 눌러도 반응 없는 메뉴는 신뢰를 떨어뜨린다. 5개를 한 번에 구현하기보다, 다른 진행 중 작업과 겹치지 않는 두 항목(반려견 프로필 관리, 고객센터)부터 정리한다.

## 범위 (Scope)

### In Scope
- 반려견 프로필 등록/조회/수정/삭제 (사용자당 여러 마리)
- 고객센터 정적 화면 (FAQ + 인스타그램 연락처)

### Out of Scope
- 배송조회 — 실제 배송 상태 개념 자체가 Order 도메인에 없고, 택배사 API 연동이 필요해 무거움 (`cart-order-payment` spec에서도 배송추적을 Out of Scope로 명시)
- 쿠폰함 / 적립금 — 별도 "쿠폰 시스템" Todo 항목에서 다룸(결제 금액 계산과 맞물려 있어 범위가 큼)
- 반려견 프로필과 주문/리뷰 등 타 도메인 연동(예: 리뷰 작성 시 반려견 선택, 사이즈 추천 반영) — 이번엔 완전히 독립된 CRUD 화면으로만 구현, 연동이 필요해지면 별도 spec
- 반려견 프로필 사진 업로드 — 이미지 업로드 인프라(스토리지 연동 등) 자체가 프로젝트에 없음(리뷰 이미지 첨부와 동일 사유). 품종/성별 기반 기본 아이콘으로 대체
- 고객센터 1:1 문의 티켓 시스템 — 백엔드 도메인 없이, 모든 문의는 인스타그램 DM으로 안내하는 정적 링크만 제공
- FAQ의 실제 배송비 정책(3,400원, 7만원 이상 무료배송, 제주·도서산간 추가 4,000원)을 결제(checkout) 로직에 반영하는 작업 — 현재 `cart-order-payment` 구현은 "배송비 없음(상품가만 결제)"으로 되어 있어 이 FAQ 문구와 실제 결제 금액이 불일치한다. 결제가 아직 샌드박스 단계라 실 고객에게 당장 영향은 없지만, 실결제 전환 전에 별도 spec으로 결제 로직을 이 배송비 정책에 맞게 수정해야 한다.

## 사용자 시나리오

### 반려견 프로필 관리
1. 마이페이지에서 "반려견 프로필 관리" 메뉴를 누르면 등록된 반려견 목록 화면으로 이동한다.
2. 등록된 반려견이 없으면 빈 상태 안내와 "반려견 등록" 버튼이 보인다.
3. "반려견 등록"을 누르면 이름(필수)/품종/생일/성별/몸무게 입력 폼이 나타난다. 이름만 입력해도 저장할 수 있다.
4. 저장하면 목록에 새 반려견 카드가 즉시 반영된다.
5. 반려견 카드의 수정 버튼을 누르면 기존 값이 채워진 폼으로 전환되고, 수정 후 저장하면 카드 내용이 갱신된다.
6. 반려견 카드의 삭제 버튼을 누르면 확인 후 삭제되고 목록에서 사라진다. 삭제 후에도 새 반려견을 다시 등록할 수 있다.
7. 예외: 이름을 비운 채 저장을 시도하면 검증 에러가 표시되고 저장되지 않는다.
8. 예외: 다른 사용자의 반려견 프로필을 직접 접근/수정/삭제 시도하면 거부된다.

### 고객센터
1. 마이페이지에서 "고객센터" 메뉴를 누르면 FAQ와 연락처가 담긴 화면으로 이동한다.
2. FAQ 항목을 누르면 답변이 펼쳐진다(아코디언).
3. 인스타그램 연락처 영역을 누르면 새 탭에서 실제 인스타그램 프로필(`https://instagram.com/momentive_official`)로 이동한다.

## 인터페이스

### API

**`GET /pets`** (인증 필요)
- Response 200: `{ pets: [{ id, name, breed, birthDate, gender, weightKg }] }` — 요청한 사용자 소유 반려견만 최신순으로 반환

**`POST /pets`** (인증 필요)
- Request: `{ name, breed?, birthDate?, gender?, weightKg? }`
- Response 201: 생성된 반려견 단건
- 에러: `VALIDATION_FAILED`(400, `name` 공백)

**`PATCH /pets/{petId}`** (인증 필요)
- Request: `POST`와 동일한 필드
- Response 200: 수정된 반려견 단건
- 에러: `VALIDATION_FAILED`(400), `PET_NOT_FOUND`(404), `FORBIDDEN`(403, 본인 소유가 아닌 경우)

**`DELETE /pets/{petId}`** (인증 필요)
- Response 204
- 에러: `PET_NOT_FOUND`(404), `FORBIDDEN`(403, 본인 소유가 아닌 경우)

### 화면

**`/mypage/pets` (반려견 프로필 목록)**
- 반려견이 없으면 빈 상태 안내 + "반려견 등록" 버튼
- 반려견이 있으면 카드 목록(이름, 품종/생일/성별/몸무게 중 입력된 값만 표시, 품종/성별 기반 기본 아이콘) + 각 카드에 수정/삭제 버튼
- "반려견 등록"/수정 버튼을 누르면 같은 화면 내에서 폼이 펼쳐짐(이름 필수, 나머지 선택 입력)
- 삭제는 확인 다이얼로그 후 진행

**`/mypage/support` (고객센터)**
- FAQ 아코디언 4개: 배송비, 결제수단, 교환/환불, 회원가입/로그인
- 인스타그램 연락처 링크(새 탭으로 `https://instagram.com/momentive_official` 열기)

**`/mypage` 메뉴 연결**
- 기존 `MENU_ITEMS`의 "반려견 프로필 관리" 항목 클릭 시 `/mypage/pets`로 이동
- "고객센터" 항목 클릭 시 `/mypage/support`로 이동
- "배송조회"/"쿠폰함"/"적립금" 3개 항목은 이번 spec에서 변경하지 않고 기존처럼 무동작 상태로 둔다

### 데이터 모델

**`Pet`**
- `id`: PK
- `user`: `User` FK (Many-to-One), 소유자
- `name`: String, not null
- `breed`: String, nullable
- `birthDate`: Date, nullable
- `gender`: Enum(`MALE`, `FEMALE`), nullable
- `weightKg`: Double, nullable
- `createdAt`: 생성 시각
