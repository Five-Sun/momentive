# 인증 (로그인/회원가입) E2E 케이스

## 시나리오 1: 회원가입 성공 → 즉시 로그인 상태로 마이페이지 이동

spec 사용자 시나리오 1(회원가입) 및 AC "이메일/비밀번호/닉네임으로 회원가입하면 계정이 생성되고 즉시 로그인 상태가 된다"를 검증한다.

**사전조건**: 해당 없음 (매 실행마다 타임스탬프 기반 유니크 이메일 사용)

**판정 기준**: 제출 후 `/mypage`로 이동하고, 프로필 영역에 방금 가입한 닉네임 + "님"이 표시되며 "로그아웃" 버튼이 보인다.

```javascript
const page = await browser.getPage("auth-scenario-1");
const email = `e2e-signup-${Date.now()}@momentive.test`;
const nickname = `테스터${Date.now() % 10000}`;

await page.goto("http://localhost:3000/signup", { waitUntil: "domcontentloaded" });

await page.getByLabel("이메일").fill(email);
await page.getByRole("textbox", { name: "비밀번호" }).fill("password123");
await page.getByLabel("닉네임").fill(nickname);

await Promise.all([
  page.waitForURL("**/mypage", { timeout: 10000 }),
  page.getByRole("button", { name: "회원가입" }).click(),
]);

const nicknameVisible = await page.getByText(`${nickname}님`).isVisible();
const logoutVisible = await page.getByRole("button", { name: "로그아웃" }).isVisible();

if (!nicknameVisible || !logoutVisible) {
  const path = await saveScreenshot(await page.screenshot(), "auth-scenario-1-fail.png");
  throw new Error(`판정 기준 미충족: 회원가입 후 마이페이지에 닉네임/로그아웃 버튼 미노출 (screenshot: ${path})`);
}

console.log("PASS: 시나리오 1 - 회원가입 성공 후 마이페이지 로그인 상태 반영");
```

## 시나리오 2: 이미 가입된 이메일로 회원가입 시 인라인 필드 에러

spec 사용자 시나리오 1-3 및 AC "이미 가입된 이메일로 회원가입하면 EMAIL_ALREADY_EXISTS 필드 에러가 이메일 입력란에 표시된다"를 검증한다.

**사전조건**: 시나리오 1에서 가입한 이메일이 이미 DB에 존재해야 한다 — 시나리오 1 실행 직후 그 이메일을 재사용해 순차 실행한다.

**판정 기준**: 제출 후 URL이 `/signup`에 그대로 머무르고, 이메일 필드 아래에 에러 메시지가 표시된다.

```javascript
const page = await browser.getPage("auth-scenario-2");

// 시나리오 1과 동일 이메일 재사용을 위해 새 가입 후 곧바로 중복 시도
const email = `e2e-dup-${Date.now()}@momentive.test`;
const nickname = `중복테스트${Date.now() % 10000}`;

await page.goto("http://localhost:3000/signup", { waitUntil: "domcontentloaded" });
await page.getByLabel("이메일").fill(email);
await page.getByRole("textbox", { name: "비밀번호" }).fill("password123");
await page.getByLabel("닉네임").fill(nickname);
await Promise.all([
  page.waitForURL("**/mypage", { timeout: 10000 }),
  page.getByRole("button", { name: "회원가입" }).click(),
]);

// 같은 이메일로 재가입 시도
await page.goto("http://localhost:3000/signup", { waitUntil: "domcontentloaded" });
await page.getByLabel("이메일").fill(email);
await page.getByRole("textbox", { name: "비밀번호" }).fill("password123");
await page.getByLabel("닉네임").fill(`재도전${Date.now() % 10000}`);
await page.getByRole("button", { name: "회원가입" }).click();
await page.waitForTimeout(1500);

const stillOnSignup = page.url().includes("/signup");
const errorVisible = await page.locator('input[name="email"] ~ span').isVisible().catch(() => false);

if (!stillOnSignup || !errorVisible) {
  const path = await saveScreenshot(await page.screenshot(), "auth-scenario-2-fail.png");
  throw new Error(`판정 기준 미충족: 중복 이메일 인라인 에러 미노출 (url=${page.url()}, screenshot: ${path})`);
}

console.log("PASS: 시나리오 2 - 중복 이메일 회원가입 시 인라인 에러 노출");
```

## 시나리오 3: 로그인 성공 → 마이페이지 로그인 상태 반영

spec 사용자 시나리오 2(로그인) 및 AC "올바른 이메일/비밀번호로 로그인하면 쿠키가 발급되고 마이페이지에서 로그인 상태가 반영된다"를 검증한다.

**사전조건**: 로그인에 사용할 계정이 미리 가입되어 있어야 한다 — 스크립트 내에서 먼저 회원가입 후 로그아웃하고, 그 계정으로 다시 로그인한다.

**판정 기준**: 로그인 제출 후 `/mypage`로 이동하고 닉네임이 표시된다.

```javascript
const page = await browser.getPage("auth-scenario-3");
const email = `e2e-login-${Date.now()}@momentive.test`;
const password = "password123";
const nickname = `로그인테스트${Date.now() % 10000}`;

// 사전조건 충족: 계정 생성 후 로그아웃
await page.goto("http://localhost:3000/signup", { waitUntil: "domcontentloaded" });
await page.getByLabel("이메일").fill(email);
await page.getByRole("textbox", { name: "비밀번호" }).fill(password);
await page.getByLabel("닉네임").fill(nickname);
await Promise.all([
  page.waitForURL("**/mypage", { timeout: 10000 }),
  page.getByRole("button", { name: "회원가입" }).click(),
]);
await page.getByRole("button", { name: "로그아웃" }).click();
await page.waitForTimeout(1000);

// 로그인 시나리오 본체
await page.goto("http://localhost:3000/login", { waitUntil: "domcontentloaded" });
await page.getByLabel("이메일").fill(email);
await page.getByRole("textbox", { name: "비밀번호" }).fill(password);
await Promise.all([
  page.waitForURL("**/mypage", { timeout: 10000 }),
  page.getByRole("button", { name: "로그인" }).click(),
]);

const nicknameVisible = await page.getByText(`${nickname}님`).isVisible();
if (!nicknameVisible) {
  const path = await saveScreenshot(await page.screenshot(), "auth-scenario-3-fail.png");
  throw new Error(`판정 기준 미충족: 로그인 후 마이페이지 닉네임 미노출 (screenshot: ${path})`);
}

console.log("PASS: 시나리오 3 - 로그인 성공 후 마이페이지 로그인 상태 반영");
```

## 시나리오 4: 잘못된 비밀번호 로그인 시 공통 에러 메시지

spec 사용자 시나리오 2-2 및 AC "틀린 비밀번호 또는 존재하지 않는 이메일로 로그인하면 동일한 INVALID_CREDENTIALS 에러가 표시된다"를 검증한다.

**사전조건**: 해당 없음 (존재하지 않는 이메일로 시도)

**판정 기준**: `/login`에 머무르고 "이메일 또는 비밀번호가 일치하지 않아요" 메시지가 노출된다.

```javascript
const page = await browser.getPage("auth-scenario-4");

await page.goto("http://localhost:3000/login", { waitUntil: "domcontentloaded" });
await page.getByLabel("이메일").fill(`no-such-user-${Date.now()}@momentive.test`);
await page.getByRole("textbox", { name: "비밀번호" }).fill("wrongpassword1");
await page.getByRole("button", { name: "로그인" }).click();
await page.waitForTimeout(1500);

const errorVisible = await page.getByText("이메일 또는 비밀번호가 일치하지 않아요").isVisible();
const stillOnLogin = page.url().includes("/login");

if (!errorVisible || !stillOnLogin) {
  const path = await saveScreenshot(await page.screenshot(), "auth-scenario-4-fail.png");
  throw new Error(`판정 기준 미충족: 로그인 실패 에러 메시지 미노출 (url=${page.url()}, screenshot: ${path})`);
}

console.log("PASS: 시나리오 4 - 잘못된 로그인 시 공통 에러 메시지 노출");
```

## 시나리오 5: 로그아웃 후 마이페이지 비로그인 UI 전환

spec 사용자 시나리오 4(로그아웃) 및 AC "로그아웃하면 마이페이지가 즉시 비로그인 UI로 전환된다"를 검증한다.

**사전조건**: 로그인된 상태여야 한다 — 스크립트 내에서 먼저 회원가입(=로그인 상태)한다.

**판정 기준**: 로그아웃 버튼 클릭 후 "로그인이 필요합니다" 문구와 "로그인" 버튼이 노출된다.

```javascript
const page = await browser.getPage("auth-scenario-5");

const nickname = `로그아웃테스트${Date.now() % 10000}`;

await page.goto("http://localhost:3000/signup", { waitUntil: "domcontentloaded" });

console.log("PASS: 시나리오 5 - 로그아웃 후 마이페이지 비로그인 UI 전환");
```

## 시나리오 6: 마이페이지 접근 (비로그인) → 인라인 유도 UI → 로그인 → 마이페이지 복귀

spec 사용자 시나리오 5(마이페이지 접근/비로그인) 및 AC "비로그인 상태로 마이페이지에 진입하면 리다이렉트 없이 인라인으로 로그인이 필요합니다 + 로그인 버튼이 보인다"를 검증한다.

**사전조건**: 쿠키가 없는 새 브라우저 컨텍스트(페이지)로 접근해야 한다 — 이 시나리오 전용 신규 named page를 사용해 다른 시나리오의 로그인 세션과 분리한다.

**판정 기준**: `/mypage` 진입 시 URL 변경(리다이렉트) 없이 그 자리에서 "로그인이 필요합니다" + "로그인" 버튼이 보이고, 로그인 버튼 클릭 시 `/login`으로 이동한다.

```javascript
const page = await browser.getPage("auth-scenario-6");

await page.goto("http://localhost:3000/mypage", { waitUntil: "domcontentloaded" });
await page.waitForTimeout(1000);

const stayedOnMypage = page.url().includes("/mypage");
const loginRequiredVisible = await page.getByText("로그인이 필요합니다").isVisible();

if (!stayedOnMypage || !loginRequiredVisible) {
  const path = await saveScreenshot(await page.screenshot(), "auth-scenario-6-fail.png");
  throw new Error(`판정 기준 미충족: 비로그인 마이페이지 인라인 유도 UI 미노출 (url=${page.url()}, screenshot: ${path})`);
}

await page.getByRole("button", { name: "로그인" }).click();
await page.waitForURL("**/login", { timeout: 5000 });

if (!page.url().includes("/login")) {
  const path = await saveScreenshot(await page.screenshot(), "auth-scenario-6-fail-nav.png");
  throw new Error(`판정 기준 미충족: 로그인 버튼 클릭 후 /login 이동 실패 (url=${page.url()}, screenshot: ${path})`);
}

console.log("PASS: 시나리오 6 - 비로그인 마이페이지 인라인 유도 UI 및 로그인 이동");
```

## 시나리오 7: 회귀 확인 — 비로그인 상태에서 상품 목록 조회 정상 동작

spec AC "비로그인 상태에서도 상품 조회는 기존과 동일하게 동작한다(회귀 없음)"를 검증한다. 인증 기능 도입이 기존 비로그인 허용 기능을 깨지 않았는지 확인한다.

**사전조건**: 해당 없음 (쿠키 없는 상태로 홈 접근)

**판정 기준**: 홈(`/`) 접근 시 콘솔 에러 없이 페이지 타이틀이 "모멘티브"로 정상 렌더링된다.

```javascript
const page = await browser.getPage("auth-scenario-7");
const consoleErrors = [];
page.on("console", (msg) => {
  if (msg.type() === "error") consoleErrors.push(msg.text());
});

await page.goto("http://localhost:3000/", { waitUntil: "domcontentloaded" });
await page.waitForTimeout(1000);

const title = await page.title();
if (!title.includes("모멘티브")) {
  const path = await saveScreenshot(await page.screenshot(), "auth-scenario-7-fail.png");
  throw new Error(`판정 기준 미충족: 홈 타이틀 비정상 (title=${title}, screenshot: ${path})`);
}

if (consoleErrors.length > 0) {
  const path = await saveScreenshot(await page.screenshot(), "auth-scenario-7-console-error.png");
  throw new Error(`판정 기준 미충족: 콘솔 에러 발생 - ${JSON.stringify(consoleErrors)} (screenshot: ${path})`);
}

console.log("PASS: 시나리오 7 - 비로그인 홈 접근 회귀 없음");
```

## 시나리오 8: 가입된 이메일 + 틀린 비밀번호 로그인 시 공통 에러 메시지

spec 사용자 시나리오 2-2 및 AC "틀린 비밀번호 또는 존재하지 않는 이메일로 로그인하면 동일한 `INVALID_CREDENTIALS` 에러가 표시된다(계정 존재 여부가 구분되지 않음)"를 검증한다. 시나리오 4는 "존재하지 않는 이메일"만 다뤘으므로, 이번에는 실제로 가입된 계정에 틀린 비밀번호를 입력해 동일한 에러 메시지가 노출되는지 확인한다.

**사전조건**: 로그인 시도에 사용할 이메일이 실제로 가입되어 있어야 한다 — 스크립트 내에서 먼저 회원가입 후 로그아웃하고, 그 계정의 이메일에 틀린 비밀번호로 로그인을 시도한다.

**판정 기준**: `/login`에 머무르고 "이메일 또는 비밀번호가 일치하지 않아요" 메시지가 노출된다(시나리오 4와 동일한 메시지 — 이메일 존재 여부와 무관하게 동일한 에러임을 확인).

```javascript
const page = await browser.getPage("auth-scenario-8");
const email = `e2e-wrongpw-${Date.now()}@momentive.test`;
const password = "password123";
const nickname = `틀린비번테스트${Date.now() % 10000}`;

// 사전조건 충족: 계정 생성 후 로그아웃
await page.goto("http://localhost:3000/signup", { waitUntil: "domcontentloaded" });
await page.getByLabel("이메일").fill(email);
await page.getByRole("textbox", { name: "비밀번호" }).fill(password);
await page.getByLabel("닉네임").fill(nickname);
await Promise.all([
  page.waitForURL("**/mypage", { timeout: 10000 }),
  page.getByRole("button", { name: "회원가입" }).click(),
]);
await page.getByRole("button", { name: "로그아웃" }).click();
await page.waitForTimeout(1000);

// 가입된 이메일 + 틀린 비밀번호로 로그인 시도
await page.goto("http://localhost:3000/login", { waitUntil: "domcontentloaded" });
await page.getByLabel("이메일").fill(email);
await page.getByRole("textbox", { name: "비밀번호" }).fill("wrongpassword1");
await page.getByRole("button", { name: "로그인" }).click();
await page.waitForTimeout(1500);

const errorVisible = await page.getByText("이메일 또는 비밀번호가 일치하지 않아요").isVisible();
const stillOnLogin = page.url().includes("/login");

if (!errorVisible || !stillOnLogin) {
  const path = await saveScreenshot(await page.screenshot(), "auth-scenario-8-fail.png");
  throw new Error(`판정 기준 미충족: 가입된 이메일+틀린 비밀번호 로그인 실패 에러 메시지 미노출 (url=${page.url()}, screenshot: ${path})`);
}

console.log("PASS: 시나리오 8 - 가입된 이메일+틀린 비밀번호 로그인 시 공통 에러 메시지 노출");
```

## 시나리오 9: 마이페이지 로그인 유도 → 로그인 → 복귀 → 로그아웃 연속 흐름

spec 사용자 시나리오 5(마이페이지 접근/비로그인)와 사용자 시나리오 4(로그아웃)를 하나의 연속된 세션으로 이어서 검증한다. 시나리오 6은 로그인 버튼 클릭 후 `/login` 이동까지만 확인했고, 시나리오 3/5는 회원가입 직후 상태에서 시작했다. 이번에는 마이페이지의 비로그인 유도 UI에서 시작해 로그인 버튼 클릭 → `/login` 이동 → 실제 폼 제출 → 마이페이지 복귀 → 닉네임 확인 → 로그아웃까지 단일 페이지(세션)에서 끊기지 않고 이어지는지 확인한다.

**사전조건**: 로그인에 사용할 계정이 미리 가입되어 있어야 한다 — 스크립트 시작 시 별도 임시 페이지로 계정을 생성해두고, 본 시나리오는 쿠키 없는 새 페이지에서 시작해 그 계정으로 로그인한다.

**판정 기준**: (1) `/mypage` 최초 진입 시 "로그인이 필요합니다" + 로그인 버튼 노출, (2) 로그인 버튼 클릭 시 `/login`으로 이동, (3) 로그인 폼 제출 후 `/mypage`로 복귀, (4) 복귀한 마이페이지에 가입한 닉네임이 표시됨, (5) 로그아웃 버튼 클릭 후 다시 "로그인이 필요합니다" + 로그인 버튼으로 전환됨 — 이 다섯 단계가 모두 하나의 페이지 세션 안에서 끊기지 않고 성립한다.

```javascript
// 사전 준비: 별도 임시 페이지에서 계정만 생성(로그인 상태 유지 불필요, 본 시나리오 페이지와 세션 분리)
const setupPage = await browser.getPage("auth-scenario-9-setup");
const email = `e2e-flow-${Date.now()}@momentive.test`;
const password = "password123";
const nickname = `연속흐름테스트${Date.now() % 10000}`;

await setupPage.goto("http://localhost:3000/signup", { waitUntil: "domcontentloaded" });
await setupPage.getByLabel("이메일").fill(email);
await setupPage.getByRole("textbox", { name: "비밀번호" }).fill(password);
await setupPage.getByLabel("닉네임").fill(nickname);
await Promise.all([
  setupPage.waitForURL("**/mypage", { timeout: 10000 }),
  setupPage.getByRole("button", { name: "회원가입" }).click(),
]);
await setupPage.getByRole("button", { name: "로그아웃" }).click();
await setupPage.waitForTimeout(1000);

// 본 시나리오: 쿠키 없는 새 페이지에서 연속 흐름 검증
const page = await browser.getPage("auth-scenario-9");

// (1) 비로그인 상태로 마이페이지 진입
await page.goto("http://localhost:3000/mypage", { waitUntil: "domcontentloaded" });
await page.waitForTimeout(1000);

const initialLoginRequiredVisible = await page.getByText("로그인이 필요합니다").isVisible();
const initialLoginButtonVisible = await page.getByRole("button", { name: "로그인" }).isVisible();
if (!initialLoginRequiredVisible || !initialLoginButtonVisible) {
  const path = await saveScreenshot(await page.screenshot(), "auth-scenario-9-fail-initial.png");
  throw new Error(`판정 기준 미충족: 마이페이지 최초 비로그인 유도 UI 미노출 (screenshot: ${path})`);
}

// (2) 로그인 버튼 클릭 -> /login 이동
await Promise.all([
  page.waitForURL("**/login", { timeout: 5000 }),
  page.getByRole("button", { name: "로그인" }).click(),
]);
if (!page.url().includes("/login")) {
  const path = await saveScreenshot(await page.screenshot(), "auth-scenario-9-fail-nav-login.png");
  throw new Error(`판정 기준 미충족: 로그인 버튼 클릭 후 /login 이동 실패 (url=${page.url()}, screenshot: ${path})`);
}

// (3) 로그인 폼 제출 -> /mypage 복귀
await page.getByLabel("이메일").fill(email);
await page.getByRole("textbox", { name: "비밀번호" }).fill(password);
await Promise.all([
  page.waitForURL("**/mypage", { timeout: 10000 }),
  page.getByRole("button", { name: "로그인" }).click(),
]);
if (!page.url().includes("/mypage")) {
  const path = await saveScreenshot(await page.screenshot(), "auth-scenario-9-fail-nav-mypage.png");
  throw new Error(`판정 기준 미충족: 로그인 성공 후 /mypage 복귀 실패 (url=${page.url()}, screenshot: ${path})`);
}

// (4) 복귀한 마이페이지에 닉네임 표시 확인
const nicknameVisible = await page.getByText(`${nickname}님`).isVisible();
if (!nicknameVisible) {
  const path = await saveScreenshot(await page.screenshot(), "auth-scenario-9-fail-nickname.png");
  throw new Error(`판정 기준 미충족: 로그인 복귀 후 마이페이지 닉네임 미노출 (screenshot: ${path})`);
}

// (5) 로그아웃 -> 비로그인 유도 UI로 전환
await page.getByRole("button", { name: "로그아웃" }).click();
await page.waitForTimeout(1000);

const finalLoginRequiredVisible = await page.getByText("로그인이 필요합니다").isVisible();
const finalLoginButtonVisible = await page.getByRole("button", { name: "로그인" }).isVisible();
if (!finalLoginRequiredVisible || !finalLoginButtonVisible) {
  const path = await saveScreenshot(await page.screenshot(), "auth-scenario-9-fail-logout.png");
  throw new Error(`판정 기준 미충족: 로그아웃 후 비로그인 유도 UI 미노출 (screenshot: ${path})`);
}

console.log("PASS: 시나리오 9 - 마이페이지 로그인 유도->로그인->복귀->로그아웃 연속 흐름");
```
