# cart-order-payment / Phase 4 — 2026-08-30

## 실패

Phase 4 수동 검증(브라우저, 토스 샌드박스) 중 "결제위젯 렌더링, 결제 성공/실패 시나리오 화면 전환 확인" 항목이 결제수단 선택 UI 자체가 렌더링되지 않아 완결되지 못함. 실패/미방치 만료 경로(주문 실패 화면 전환)는 정상 확인됐으나, confirm 성공 경로(결제위젯 → 실제 결제 완료 → `PAID` 전환)는 끝까지 검증하지 못했다.

## 원인

Toss Payments 클라이언트 키(`test_ck_...`)로 결제위젯 전용 API(`GET /v1/payment-widget/widget-groups/keys?variantKey=DEFAULT`)를 호출하면 401 `{"code":"4000","message":"인증되지 않은 시크릿 키 혹은 클라이언트 키 입니다."}`가 반환된다. 같은 계정의 시크릿 키(`test_sk_...`)는 `/v1/payments/confirm`에서 정상 인증(가짜 데이터로 인한 404만 발생)되므로 키 형식/오탈자 문제는 아니다.

사용자 확인 결과 Toss 개발자센터에서 계정 가입만 완료했고 별도의 "상점(스토어) 등록" 절차(사업자 정보 또는 개인 인증 기반)를 진행하지 않은 상태였다. 결제위젯 API는 상점 단위로 매핑되는 리소스로 추정되며, 상점 등록이 안 된 상태에서는 클라이언트 키가 발급/노출되어 있어도 결제위젯 기능 자체가 활성화되지 않는 것으로 보인다. 사업자 등록이 필요한 절차라 이번 세션에서는 진행하지 않기로 결정.

## 조치

미조치 — 사용자가 사업자 정보(또는 개인 인증)로 Toss 상점 등록을 완료한 뒤, 재발급/재확인된 키를 `frontend/.env.local`(`NEXT_PUBLIC_TOSS_CLIENT_KEY`)과 백엔드 환경변수(`MOMENTIVE_TOSS_SECRET_KEY`)에 반영하고 결제위젯 렌더링부터 confirm 성공까지 재검증한다. 코드 변경은 필요 없을 것으로 추정(연동 로직 자체는 시크릿 키 인증까지 정상 동작 확인됨).

## 재발 방지

외부 결제/PG 연동 작업 착수 전, "API 키 발급"과 "가맹점(상점) 활성화"가 별개 단계인지 해당 PG사 문서에서 먼저 확인한다 — 키가 유효해 보여도 상점 미등록 시 특정 API군(이번 경우 결제위젯)만 401로 거부될 수 있다.
